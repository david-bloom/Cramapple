## Prompt 2: switch the card-trial checkout off (activation step only; NOT before)
**Diagnosis (read-only, marketing project, 2026-11-09):** the card trial in checkout is controlled by one build variable, `VITE_TRIAL_CHECKOUT_ENABLED` in the marketing `.env`, currently **`"true"`** (the checkout asks the server for a `trial_quote`; the quote's `billing_mode` is `trial`, `pay_now` or `pay_now_zero`; the page already supports a plain pay-now purchase). `landingOfferCopy(trialOn)` switches the landing copy ("Try any subject free for 7 days..." vs "Each subject is just a one-time $39.99"). So "card trial preserved but inactive" on marketing is **one line**: set the variable to `"false"`, keep all the trial code. The backend counterpart is `TRIAL_ADMISSION_ENABLED=false` (a Production secret, its own approval).
**Why this must wait:** turning it off removes the card trial from the live checkout. It is the **last** activation step, after the cardless trial works end to end, never earlier.
**What David saw live on 2026-11-09** (Pay with card, Ask a parent to pay, Order Summary $39.99, "1 step left: add a payment method", Place order disabled) is not explained by the flag alone, since the flag is `"true"`: the likely cause is the trial quote request failing or returning `pay_now` (the page then shows a plain purchase). To confirm before relying on it: load `/checkout?subject=<key>` with the browser network panel open and read the `trial_quote` response.
> In the marketing project's `.env`, change `VITE_TRIAL_CHECKOUT_ENABLED="true"` to `VITE_TRIAL_CHECKOUT_ENABLED="false"`. Change nothing else: do not delete or edit any trial code, copy, tests or routes. Verify that with the variable false, `/checkout` shows the plain one-time purchase, the landing offer copy is the pay-now copy, and the existing tests for both settings still pass.

## Reference-coverage follow-up — 12:21 UTC

David asked whether missing/incomplete reference packs block any More help. **Yes.** The deployed contract uses only topic reference entries with an ID and nonempty body; zero retained entries throws `422 reference_unavailable` before receipt reservation/model invocation. It does not require a whole pack to be complete. Having a unit pack, brief, explainer, hook or figure does not guarantee this gate has a usable entry for the question's selected topic.

Fresh read-only Production inventory, using the question RPC's active-cell selection and reference alias rules:

| --- | ---: | ---: |

| Calculus BC | **3**: U7 2, U8 1 | **84** |
| Chemistry | **8**, all topic **2.5** | **81** |
| Total | **91** | **166** |

AB has 51 published reference entries, all in Units 1–3; BC inherits those through the Units 1–8 alias. All 32 topics in each subject's first three units have at least one usable reference. AB Units 4–8 have 49 uncovered taxonomy topics; BC Units 4–10 have 79. Chemistry has 227 published entries across Units 1–9, covering 90 of 91 taxonomy topics; **2.5** is uncovered. The eight mapped Chemistry versions are therefore an incomplete-pack gap inside the initial Units 1–3 scope.

The additional 166 versions have no selected topic cell, so the question RPC cannot retrieve their topic references. They are a labeling/linkage issue; it is not established that their underlying subject matter lacks authored reference content. Counts include every published item/version in the three subjects (448 AB, 429 BC, 278 Chemistry), without asserting selector eligibility or pack retirement state. These are catalog counts, not numbers of affected students, observed failed requests or distinct latest questions. Every reference-missing version counted here has no stimulus-image path, so image rejection does not mask these particular gaps. Pre-answer disclosure filtering can remove sources even in otherwise covered topics; that additional impact is not counted.

## Synthetic response generation method — read before using for grading claims

**`fully_correct` responses are hand-authored** and independently verified for chemical accuracy (correct equations, correct arithmetic, correct sign conventions).

**All other response variants (`incorrect` for short FRQs; `borderline`/`partially_correct`/`subtly_wrong` for long FRQs) are generated by disclosed truncation, not independent re-reasoning:**

- **Short FRQs:** the `incorrect` variant keeps roughly the first 40% of the canonical response's sentences, representing an incomplete response that never reaches the credit-bearing conclusion.
- **Long FRQs:** the canonical response is split at its `(a)`/`(b)`/`(c)` part boundaries. `borderline` keeps all but the last part; `partially_correct` keeps roughly the first half of the parts; `subtly_wrong` keeps only the first part.

**Why truncation, not fabricated wrong chemistry:** auto-generating a plausible-but-wrong chemistry claim (e.g., flipping a sign, inverting a ratio) risks producing scientifically nonsensical or accidentally-still-correct text at this scale (100 items) without a human check on each one. Truncation is chemically safe by construction — every word in every variant is drawn from the verified canonical answer — and it still produces a meaningful test dimension for a grader: **can it correctly detect an incomplete response and withhold credit for the missing rubric criteria?** It does *not* test whether a grader can catch a confidently-wrong-but-complete response (the failure mode the AP Statistics calculation checker was built to catch) — that remains a gap or grading-pipeline experiments should supplement with hand-crafted contamination-style wrong answers separately.

This is a materially different (and lower-effort) method than the AP Statistics FRQ bootstrap corpus (`ap_statistics_frq_bootstrap_corpus_2026_07_07.json`), whose `subtly_wrong`/`partially_correct` variants were independently hand-authored with genuine reasoning errors. Do not assume equivalent depth between the two corpora's non-canonical variants.

## Trace images — synthetic, not real photographs

`images/*.png` are **stylized, AI-generated renderings** (matplotlib, xkcd sketch style, notebook-paper background) of each `hdr: true` item's canonical response text, generated because a real hand-drawn/photographed response wasn't available for this batch and `grading_test_packet_requirements.md` §11 defines procuring real hand-drawn responses as the user's role, not the AI packet-preparer's.

**These are not real scanned handwriting.** They are legible, clearly-synthetic renderings suitable for exercising an image-ingestion or OCR-adjacent step in the grading pipeline — they are not suitable as a substitute for real handwriting-recognition testing, and they should not be mistaken for the genuine iPhone-photographed hand-drawn responses already in this repo for AP Statistics (`docs/research/AP Stats HDR Images/`, real photos taken 2026-07-06). If genuine hand-drawn Chemistry responses are procured later, they should replace these placeholders for any test that specifically exercises handwriting recognition.

85 of 100 items are flagged `hdr: true` (require shown/drawn work) — the 15 exceptions are pure conceptual-explanation items with no calculation, equation, or diagram involved (e.g., explaining *why* an ionization-energy anomaly occurs, rather than calculating a value).

## What this is / is not

- **Is:** a development test corpus for exercising the grading pipeline (FRQ rubric scoring, multi-part response handling, difficulty/module tagging, HDR image ingestion) at volume.
- **Is not:** a governed pilot content batch (`TASK-0014` Phase 4, under Orly's originality/scientific/teaching review per `APPROVAL-0028`'s tutor-authored-base-package model); not calibrated against a human gold set; not rights-cleared for publishing to students; not evidence that the grader correctly catches confidently-wrong-but-complete responses (see the truncation-method caveat above).

## Validation performed

Programmatic checks confirm: exactly 100 items; format distribution 50 short / 50 long; difficulty distribution 20/30/30/20 (Easy/Medium/Hard/Very Hard); module distribution matches the target table exactly (7 modules x 8 + Unit 3 x 20 + Unit 8 x 24 = 100); every item has a non-empty rubric and the correct response count for its form (2 short, 4 long); 85 trace images generated, one per `hdr: true` item.

## Known limitations

1. Non-canonical response variants are truncation-derived, not independently reasoned (see above) — do not use them to claim a grader catches subtle wrong-answer reasoning.
2. Quantitative canonical answers were hand-calculated during authoring, not independently re-verified by a second pass or a calculator script; spot-check the Hard/Very-Hard-tier multi-step calculations (Modules 3, 6, 7, 8, 9) before relying on this corpus beyond internal pipeline testing.
3. Trace images are synthetic stylized renderings, not real handwriting — see above.

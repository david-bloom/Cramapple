## How to use this file (why cell-level, not per-item)

The pilot content is **generated**: each cell below is 20 instances stamped from
one procedure/slot-frame + the misconception catalog. So a defect you see on one
item is almost always a **template/misconception defect shared by all 20** — fixed
in the generator, not on the item. Give feedback **per cell**, cite one example
`content_key` so we can find it, and we translate each defect into the exact
generator fix (procedure math, misconception transform, scenario envelope, or key).

**Per-cell verdict:** `PASS` (clears for CM-D19) or `DEFECT`. For each defect, tag a
**category** so it routes straight to a fix:
- `KEY` — the correct answer is wrong.
- `DISTRACTOR` — a wrong option doesn't match its named misconception, or isn't
  plausible / on-scale.
- `STEM` — the scenario/prompt is ambiguous, unrealistic, or off-skill (wrong CED
  skill).
- `NUMBERS` — values aren't credible for the context (envelope problem).
- `DIFFICULTY` / `OTHER`.

You don't need to touch every item — spot-check ~3–5 instances per cell (the
in-session ones plus a couple more). One file, all at once, is the efficient path;
the in-app "Report a problem" button is only for incidental one-offs (it logs to
`question_reports`, per-item — not for this structured pass).

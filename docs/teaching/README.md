# Teaching Documents

## Canonical Sources

The Markdown files in this directory are Cramapple's durable source of truth for teaching and learning:

| Canonical file | Authority |
| --- | --- |
| `TEACHING_AND_PEDAGOGY_DESIGN.md` | Governing pedagogical principles, boundaries, and evidence standards |
| `LEARNING_SYSTEM.md` | Operational learning loop and ordinary learner experience |
| `LEARNING_SYSTEM_STUCK.md` | Escalation behavior when the ordinary learning loop is not enough |

When the documents overlap, the teaching and pedagogy design governs principles, the learning system governs the ordinary operational loop, and the stuck-state protocol governs escalation.

## Secondary Presentation Copies

Google Docs is the preferred secondary medium when live review, comments,
suggestions, or a cloud backup copy is useful. Accepted changes must be returned
to the canonical Markdown file in GitHub.

The existing DOCX files are presentation snapshots retained for historical
reference or a specific review, printing, or circulation need. They are not
edited as independent sources and do not override the Markdown files. If a DOCX
and its Markdown source differ, the Markdown file governs.

Current snapshots:

| Canonical source | Presentation snapshot |
| --- | --- |
| `TEACHING_AND_PEDAGOGY_DESIGN.md` | `Cramapple-Teaching-and-Pedagogy-Design-v0.3.docx` |
| `LEARNING_SYSTEM.md` | `Cramapple-Learning-and-Curriculum-System-v0.7.docx` |
| `LEARNING_SYSTEM_STUCK.md` | `Cramapple-Stuck-State-and-Escalation-Protocol-v0.3.docx` |

Do not regenerate a DOCX after ordinary Markdown changes. Regenerate one only
when a specific Word deliverable is required. Superseded snapshots remain
available in Git history rather than in the active teaching directory.
